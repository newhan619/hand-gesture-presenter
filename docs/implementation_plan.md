# 단계별 구현 계획

2026-11-15 사용자가 최종 제안서를 기준으로 작업을 요청하여 로컬 초기 구현을 진행했다. `main.py`, `presenter/`, 전용 `.venv`, 모의 실행과 자동 테스트, 한국어 설치 안내를 준비했다. 카메라 없는 PC에서 검사 가능한 범위와 실제 장치 검증을 구분한다. 아래 단계 표의 하드웨어 완료 기준은 팀원 시험 후에만 완료 처리한다.

## 2026-11-15 현재 상태

- 최종본 기준: 핵심 기능 세 가지를 구현하고 선택 기능인 사용자 제스처 학습과 판서는 제외했다.
- 환경: Python 3.12.14 64비트로 `.venv`를 만들었다. 초기 후보 3.11 대신 실제 설치·검증한 3.12를 팀 설치 기준으로 삼는다.
- 로컬 확인: 패키지 의존성, import, 공식 모델 파일·로딩과 검은 영상 추론, 합성 좌표와 모의 제스처, 카메라 오류·종료 처리의 자동 검증.
- 실제 확인 대기: 웹캠 열기, 실제 손 모양 정확도, 스와이프 인식률, PPT 창 판별과 Ctrl+L/Ctrl+A, FPS·조명·거리와 연속 시연.
- 실행과 인계: `README.md`, `docs/camera_test_checklist.md`, `.github/ISSUE_TEMPLATE/camera-test.md` 참조. 로컬 구현 후 사용자의 요청으로 소스·안내 문서·자동 테스트를 공개 저장소에 반영하는 단계로 진행했다. 실제 장치 검증은 별도이며 팀원 알림은 전송하지 않는다.

## 카메라가 없는 개발 환경과 팀원 협업

사용자 PC에는 카메라가 없다. 코드를 작성하고 카메라 없이 검증하는 작업은 사용자 측에서 진행하며, 실제 웹캠 인식과 PowerPoint 시연은 카메라가 있는 팀원이 담당한다. 개발 결과는 공개 GitHub 저장소를 통해 공유한다. 초기 구현 코드와 설치 안내, 테스트와 체크리스트를 공유 대상에 포함하며, 실제 장치 확인 결과를 받아 개선한다.

- 사용자 측: 손 좌표 예시와 시간 데이터를 입력해 손가락 판별, 스와이프, 모드 전환, 쿨다운을 검증한다. 입력 전송을 끈 모의 실행 모드를 먼저 만들고, AI 코드의 이해와 수정 결과를 기록한다.
- 카메라 보유 팀원: 설치 안내대로 실행하고 카메라 열기, 손 검출, 인식률, 조명·거리, 처리 속도, 실제 슬라이드 이동과 포인터 동작을 확인한다.
- 공유 방식: 단계별 변경을 GitHub에 올리고 팀원이 같은 커밋으로 테스트한다. GitHub 이슈에 실행 명령, 버전, 기대 결과와 실제 결과, 오류 메시지, 재현 절차를 남긴다. 팀원의 확인 결과를 받은 뒤 다음 카메라 의존 단계로 넘어간다.
- 테스트 자료: 직접 촬영한 손 영상이나 랜드마크 기록을 팀원이 제공할 경우 재생 입력으로 같은 실패를 재현할 수 있게 설계한다. 모의 입력과 녹화 재생 통과는 실제 웹캠 테스트 통과와 구분한다.
- 공개 범위: 소스, 사용법, 원리 설명, 개인정보를 제거한 개발 기록을 공유한다. `.venv`, 임시 렌더링 파일, 원본 수업 안내, 실명·학번, 개인 촬영 영상과 수집 데이터는 기본적으로 공개 업로드에서 제외한다. 제안서 공유 시에도 개인정보 포함 여부를 확인한다.
- 학습 범위: 핵심 3개는 사전 학습된 손 모델과 규칙 기반 제스처로 구현하므로 팀원이 별도 모델을 학습할 필요는 없다. 사용자 제스처 등록을 선택 기능으로 진행할 때만 팀원 PC에서 좌표 수집과 분류기 학습을 맡긴다.

구현 첫 단계에는 `.gitignore`, 한국어 설치 안내, 카메라 테스트 체크리스트, 이슈 기록 양식을 준비한다. 카메라 없는 PC에서 실시간 인식 검증을 완료했다고 보고하지 않는다.

## 초기 규칙과 조정 방법

- 좌표계: 사용자가 보는 반전 미리보기에서 오른쪽은 다음 장, 왼쪽은 이전 장이다. 제스처 좌표계와 화면 표시를 일치시킨다.
- 손가락 판별: 관절이 충분히 펴졌는지 각도와 상대 위치로 판단한다. 엄지는 손의 방향과 별도 기준을 고려한다. 화면의 y좌표 비교만으로 모든 방향을 처리한다고 가정하지 않는다.
- 스와이프: 편 손 모양을 먼저 5프레임 확인하고, 0.5초 이내 영상 너비 20% 이상의 수평 이동과 수평/수직 이동 비율을 확인한다. 주먹 등 중립 자세로 돌아오고 쿨다운이 끝나야 다시 입력한다.
- 쿨다운: 프레임 수가 아닌 단조 증가 시계를 사용해 슬라이드 입력 뒤 1초 동안 추가 슬라이드 입력을 차단한다.
- 유지 프레임: 모양이 연속 5프레임 같아야 인정한다. 처리 속도에 따라 반응 시간이 달라지므로 실제 FPS를 기록하고 조정한다.
- 스무딩: 이전 보정 좌표 70%와 현재 좌표 30%를 섞는다. 흔들림 감소와 추적 지연을 함께 비교해 비율을 조정한다. 포인터 진입·손 재검출 시 과거 좌표를 초기화한다.
- 포커스: PowerPoint 슬라이드 쇼를 활성 창으로 둔다. 미리보기 클릭 시 입력 대상이 달라질 수 있으므로 실발표 조건에서 확인한다. 기본 범위는 단일 모니터이다.

모든 수치는 초기 가설이며 실행으로 조정한다. 핵심 안정성에 영향을 주는 조건은 한 번에 하나씩 바꿔 전후 결과를 기록한다.
