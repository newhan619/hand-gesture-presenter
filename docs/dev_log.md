## 2026-11-11 제안서 작성

**진행 내용:** 사용자 요청과 수업 안내, 샘플의 구성을 바탕으로 제안서와 요구사항을 한 Word 파일로 작성했다. 핵심 기능 3개와 선택 기능을 구분하고 초기 제스처 규칙과 검증 목표를 정했다.

**사전 확인:** MediaPipe 공식 설치 문서는 Python 3.9~3.14를 지원 범위로 안내한다. Python 3.11 64비트를 개발 후보로 정했으며, 실제 가상환경과 패키지 설치는 사용자 확인 후 진행한다. 최신 Tasks API의 Hand Landmarker를 우선 검토한다. OpenCV는 GUI 배포판 하나만 사용한다.

**AI 초안:** 이번 단계에서는 프로그램 코드를 생성하거나 실행하지 않았다. 제안서의 프레임 수, 이동 거리, 쿨다운 및 스무딩 수치는 시험할 초기값이며 검증된 결과가 아니다.

**요구사항을 구체화한 내용:** 반전된 미리보기 기준 오른쪽 스와이프를 다음 장으로 정의했다. 포인터와 스와이프를 동시에 실행하지 않도록 모드를 나누고, 손 미검출 시 좌표 이력을 초기화하는 계획을 넣었다. 이는 예상 충돌을 줄이기 위한 설계이며 실제 버그 수정 사례가 아니다.

**남은 확인:** 개발 Python의 로컬 설치 여부, MediaPipe와 OpenCV 의존성, 웹캠 사용, PowerPoint Ctrl+L 및 Ctrl+A 동작과 창 포커스, 발표 PC의 처리 속도.

**문서 검증:** LibreOffice가 설치되어 있지 않아 표준 렌더러의 변환이 실패했다. 설치된 Word의 PDF 내보내기로 대체하여 검토했다. 첫 결과는 기본 문서 스타일의 줄 간격과 제목 테두리 때문에 8장이 되었으며, 문서 격자와 제목 테두리를 제거하고 본문 11pt·줄 간격 16pt, 표 줄 간격 14pt로 조정해 A4 4장으로 맞췄다. 모든 페이지를 이미지로 확인했다. 이는 문서 제작 이력이며 프로그램 버그 수정 사례가 아니다.

**참고 저장소 상태:** baukk/Gesture-Recognition의 설명은 확인했다. ishant617/hand-gesture-control은 본문 접근에 실패하여 추가 검토 후보로만 기재했으며 동작 원리의 근거로 삼지 않았다.

## 2026-11-11 카메라 보유 팀원과 협업 방식 변경

**사용자 환경:** 사용자 PC에는 카메라가 없어 실제 웹캠 테스트는 카메라를 보유한 팀원이 진행한다. 공개 GitHub 저장소로 코드와 실행 안내를 공유하고, 테스트 결과를 받아 개선하는 방식으로 계획을 변경했다.

**검증 분담:** 사용자 측에서는 모의 랜드마크와 시간을 입력하는 로직 검증을 진행한다. 카메라 보유 팀원은 웹캠 인식, 실제 입력 전송, PowerPoint 포인터, 조명과 거리별 동작을 확인한다. 테스트한 커밋과 환경을 기록하고, 실제 하드웨어 확인 전에는 해당 기능을 검증 완료로 표시하지 않는다.

**학습 여부:** 핵심 기능에는 사용자 데이터로 별도 학습하는 단계가 필수는 아니다. 선택 기능인 사용자 제스처 등록을 진행할 경우에만 팀원이 좌표 수집과 분류기 학습을 수행한다.

**현재 상태:** 협업 계획만 수정했다. 프로그램 구현, 가상환경 생성, GitHub 저장소 생성과 업로드, 팀원에게 알림 전송은 수행하지 않았다.

## 2026-11-15 최종 제안서 기반 로컬 초기 구현

**구현 목표:** 최종본의 세 가지 핵심 기능에 맞춰 손 인식·관절 표시, 스와이프와 검지 포인터, 유지 프레임·쿨다운·스무딩을 구현했다. 사용자 제스처 학습과 판서는 구현하지 않았다. Word 제안서는 수정하지 않았다.

**실행 환경:** 일반 설치 Python과 `py` 런처는 확인되지 않았으나 Codex가 제공하는 Python 3.12.14 64비트를 사용할 수 있어 프로젝트 `.venv`를 만들었다. MediaPipe 1.2.3, opencv-contrib-python 4.14.0.94, NumPy 2.5.4, PyAutoGUI 0.9.54를 설치했다. MediaPipe의 의존성에 맞춰 GUI OpenCV는 contrib 배포판 하나만 사용했다. 전체 설치 버전은 `requirements.lock.txt`에 기록했다.

**AI 초안과 원리:** 카메라 처리와 제스처 계산을 분리했다. `core.py`는 관절 각도·상대 거리로 손가락을 판별하고, 시간과 좌표를 받아 이벤트만 만든다. 실제 입력은 `output.py`에 모았다. 모양을 5프레임 유지한 뒤 인정하고, 편 손의 손바닥 중심이 0.5초 내 너비 20% 이상 이동하면 방향을 판단한다. 한 번 넘긴 뒤에는 주먹 복귀와 1초 경과를 모두 요구한다. 포인터 모드에서는 슬라이드 이벤트가 발생하지 않는다.

**실제 발견한 문제와 수정:**

- 느린 이동 테스트에서 준비 위치를 x=0.4로 둔 뒤 첫 이동 좌표를 x=0.2로 넣어, 테스트 자체가 빠른 왼쪽 스와이프를 만들었다. 준비 위치를 x=0.2로 맞춰 연속적인 느린 이동으로 수정했다. 이 문제는 제스처 알고리즘의 결함이나 실제 웹캠 실패로 기록하지 않는다.
- `run.ps1 -Mode demo` 실행 시 인자가 `- - d e m o`로 전달되어 argparse가 종료 코드 2를 반환했다. PowerShell `switch` 결과가 값 하나일 때 문자열이 되고, 이를 splat하면서 글자로 분리된 것이 원인이다. `@(switch ...)`로 결과를 항상 배열로 만들었다. 수정 후 같은 명령을 다시 실행해 PASS를 확인했다.

**검증 결과:** 자동 테스트 34개 통과. 32종 손가락 조합에 회전·반전을 적용한 관절 판별, world 좌표, 좌우 스와이프 각 10회, 반복 입력과 쿨다운, 중립 복귀, 손 미검출 10초, 포인터 모드 전환·스무딩, 입력 대상 차단, 좌표 재생과 카메라 오류·종료 경로를 검사했다. 카메라 시험에는 가짜 프레임과 가짜 검출 결과를 사용했으며 실제 장치 시험이 아니다. `--demo`는 next, previous, pointer_on, pointer_off 순서와 PASS를 출력했다. `pip check`와 패키지 import가 통과했다. 공식 모델을 다운로드해 로딩하고 검은 영상에서 손 0개를 확인했다. 모델 SHA256은 `fbc2a30080c3c557093b5ddfc334698132eb341044ccee322ccf8bcf3607cde1`이다. LiteRT의 정렬·투영 관련 경고는 있었으나 추론 오류는 없었다.

**팀원 인계:** 한국어 README, 실제 카메라/PPT 체크리스트, 이슈 양식과 카메라 없는 자동 검증용 GitHub Actions 설정을 준비했다. Actions는 파일만 만들었으며 원격 실행하지 않았다. 원본 제안서·수업 안내·임시 파일·가상환경·개인 영상은 `.gitignore`에서 제외했다. 이번 작업에서 원격 저장소 갱신이나 메시지 전송은 하지 않았다.

**남은 한계와 다음 확인:** 실제 손의 인식률, 조명·거리별 FPS, PowerPoint 슬라이드 쇼 창 판별, Ctrl+L/Ctrl+A와 실제 포인터 움직임, 5분 연속 시연은 미검증이다. 합성 좌표와 검은 영상 추론 통과로 이를 성공 처리하지 않는다. 체크리스트 결과를 받은 뒤 임계값과 손 모양 규칙을 한 번에 하나씩 조정한다. 팀이 직접 코드를 이해하고 수정한 사례와 배운 점은 실제 활동 후 별도로 기록한다.
